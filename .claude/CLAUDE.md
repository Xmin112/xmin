## 开发流程（6 阶段，不可跳过）

### 阶段 0：理解与验证
- **0.1 需求澄清**：不确定时立刻停下，列出理解选项，给推荐方案，等确认后才继续
- **0.2 商业分析**（大项目必做，小工具可简化）：
  - 用户是谁？痛点是什么？
  - 竞品分析：谁在做、差距在哪、从哪里切入
  - MVP 是什么？MVP 阶段不加任何非核心功能
- **0.3 技术选型**：根据项目类型从技术栈中选，给出方案和理由

### 阶段 1：产品设计
生成以下文件（大项目等确认，小项目自行决定）：
- **PRD.md**：用户画像、功能列表、用户流程、MVP 边界
- **DESIGN.md**：风格参考、配色、字体、动效、设计原则
- **ARCHITECTURE.md**：技术栈、数据模型、API 设计、目录结构
- **1.1 原型确认**：低保真原型/线框图，确认方向后才能进入开发

### 阶段 2：TDD + 开发
- Git init → 首次 commit → 创建项目级 `.claude/CLAUDE.md` → 从 main 开功能分支
- **TDD 不可妥协**：写失败测试 → 写最小实现 → 测试通过 → 重构
- 只改必须改的代码，不做需求之外的功能
- 不过早抽象、不过度设计
- 自动 commit（中文 message），完成验证后才合并 push

### 阶段 3：验证
- **自动执行**：Type Check（`tsc --noEmit`）、基础 Lint、已有测试全部通过
- **等指令执行**：Playwright E2E、全量测试报告、最终 diff 复查
- 验证通过后合并到 main 并 push

### 阶段 4：部署
- 国际项目：Vercel / Cloudflare Pages
- 国内项目：阿里云 / 腾讯云 + Docker
- 生成 `DEPLOY.md`

### 阶段 5：验证与迭代
- 商业产品：10 → 100 → 1000 人渐进验证
- 实用工具：自己用起来，反馈 → 迭代
- 每次迭代回到阶段 2

### 阶段 6：商业化（商业产品适用）
- 不预设付费功能。用户持续使用 + 价值已验证 + 用户主动提出付费 → 才考虑
- 优先级：单次付费 → 会员 → 企业版 → 广告最后

## 功能审查规则（最高优先级）

新增任何功能前，必须回答 4 个问题：
1. 是否解决真实痛点？
2. 是否提高留存或体验？
3. 是否有助于产品目标？
4. 是否属于当前阶段范围？

**≥3 项为「否」→ 拒绝开发或推迟。**

## 技术栈

| 场景 | 默认选型 |
|---|---|
| 网站 / Web 应用 | Next.js + TypeScript + Tailwind CSS |
| 微信小程序 | Taro + React + TypeScript |
| 手机 App | React Native (Expo) / Flutter |
| 后端 / API | Go 或 Node.js (Hono / Fastify) |
| 数据库 | 小型用 SQLite，大型用 PostgreSQL |

## 红线（不可违反）

- 禁止 `any` 类型（TypeScript）
- 禁止未理解需求就写代码
- 禁止引入不必要的第三方依赖
- 禁止 `console.log` 残留到正式代码
- 禁止改动非我负责的代码（除非明确要求）
- 验证未通过禁止 push
- 禁止跳过 TDD
